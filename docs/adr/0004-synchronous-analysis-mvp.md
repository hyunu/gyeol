# ADR 0004 — MVP 분석은 요청 내 동기 실행

- 상태: **대체됨** — ADR-0007(비동기 작업 큐)로 전환
- 날짜: 2026-11-13 (대체: 2026-11-14)
- 관련: R-023, `POST /api/v1/recordings/{id}/analyze`

## 맥락

실제 AI 파이프라인(STT·화자분리·요약)은 수십 초~수 분이 걸린다. 그러나 현재는
`FakeAiPipeline` 이 즉시 결과를 돌려주며, Phase 1 의 목적은 "전 구간 데이터 흐름 검증"이다.
비동기 작업 큐를 지금 만들면 큐·워커·재시도·상태 폴링 API 까지 범위가 커진다.

## 결정

`POST .../analyze` 가 요청 안에서 파이프라인을 끝까지 실행하고 결과를 반환한다.
HTTP 상태는 계약대로 `202` 를 쓰되, 응답 시점에는 이미 분석이 완료되어 있다.

## 결과

- 장점: 큐 인프라 없이 분석·저장·조회 계약을 먼저 확정할 수 있다. 테스트가 결정적이다.
- 비용: 실제 AI 도입 시 요청 타임아웃 위험. `recordings.status='analyzing'` 이 짧게만 유지된다.
- 전환 조건: 실제 provider 연결 시 아래가 필요하다.
  1. `analysis_jobs` 테이블(또는 큐)과 워커
  2. `202` + `jobId`, `GET /analysis-jobs/{id}` 폴링
  3. 타임아웃·재시도·중복 실행 방지(현재는 `status` 가드만)
- 이 ADR 을 대체하는 새 ADR 을 작성한 뒤 전환한다.
