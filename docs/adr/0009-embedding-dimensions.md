# ADR 0009 — 임베딩 차원은 화자 256 / 텍스트 768 로 확정한다

- 상태: **채택** (D-05)
- 날짜: 2026-11-14
- 관련: W-10, `speaker_embeddings`, `conversation_embeddings`, W-18(실 provider)

## 맥락

pgvector 컬럼 차원은 한 번 정하면 모든 임베딩을 다시 계산해야 바꿀 수 있다. Phase 1 은
Fake 임베딩(768)으로 전 구간을 검증했고, 실제 provider 는 아직 정하지 않았다(ENV-05).
차원을 무기한 미루면 HNSW 인덱스·검색 튜닝·부하 측정을 시작할 수 없다.

## 결정

1. **화자 임베딩 `vector(256)`**, **텍스트 임베딩 `vector(768)`** 로 확정한다.
   - 화자 256: ECAPA-TDNN/WeSpeaker 계열 화자 임베딩의 일반적인 차원.
   - 텍스트 768: 다국어 문장 임베딩에서 흔한 차원이며, 1024/1536 으로 늘리는 것보다
     저장·검색 비용이 낮다.
2. **모델 식별자는 지금 고정하지 않는다.** W-18 에서 provider 를 붙일 때
   `conversation_embeddings.provider/model`, `speaker_embeddings.model` 에 기록한다.
   차원은 모델 선택의 제약 조건이다(256/768 을 출력하는 모델만 쓴다).
3. 검색은 **같은 모델의 임베딩끼리만 비교**해야 한다. 현재는 행에 `provider/model` 이
   있으므로, W-18 에서 검색 쿼리에 활성 모델 필터를 추가한다.
4. HNSW 인덱스는 차원 확정으로 착수 가능해졌지만, **W-18 모델·부하 측정 후** 만든다
   (`ENV-07`). 그 전에는 정확 검색(sequential scan)으로 동작한다.

## 재임베딩 전략

### 모델만 바뀌는 경우(차원 동일)

1. 새 모델로 **배치 재임베딩**하고, 대화 단위로 한 트랜잭션에서 교체한다
   (`conversation_embeddings` 는 대화당 1행).
2. `pipeline.embeddingModel`·`provider/model` 을 새 값으로 갱신한다.
3. 재임베딩이 끝난 대화만 새 모델로 검색한다(활성 모델 필터).
4. 완료 전에는 이전 모델로 검색을 유지한다. 혼합 상태를 검색에 노출하지 않는다.

### 차원이 바뀌는 경우(예: 1536)

1. 새 마이그레이션으로 `conversation_embeddings_new`(새 차원) 과 인덱스를 만든다.
2. 이중 쓰기 또는 배치 백필로 새 테이블을 채운다.
3. 검색을 새 테이블로 전환하고, 구 테이블을 읽기 전용으로 유지한 뒤 삭제한다.
4. 화자 임베딩도 같은 절차를 따른다.

> 차원 변경은 **전체 재임베딩 + 인덱스 재생성**을 뜻한다. 그래서 지금 확정한다.

## 결과

- 스키마 변경 없음: `0001_init.sql` 의 `vector(256)`·`vector(768)` 이 확정값이 된다.
- `db/README.md` 의 "실험값" 표기를 확정으로 바꾼다.
- W-17(검색 UI E2E)와 W-28(부하 측정)의 선행 조건이 해소된다.
- 남은 것: W-18 에서 모델을 정하고, 검색 모델 필터와 HNSW 파라미터를 정한다.
