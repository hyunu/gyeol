# ADR 0001 — 계약 우선(contract-first) 개발

- 상태: 채택
- 날짜: 2026-11-13
- 관련 요구사항: R-009, R-010 / 리스크: RISK-001, RISK-004

## 맥락

저장소가 빈 상태이고 최상위 기준 문서(`MEMORIAL_PROJECT_SPEC.md`)가 아직 없다.
언어·프레임워크·DB·하드웨어가 모두 미확정(OPEN-002, OPEN-003)인 상황에서 애플리케이션
코드를 먼저 작성하면, 스펙 확정 시 대규모 재작업이 발생한다.

## 결정

1. 언어 중립 계약(JSON Schema 2020-12, OpenAPI 3.1)을 코드보다 먼저 작성한다.
2. 계약은 CI 에서 자동 검증한다: 스키마 컴파일, valid/invalid 예제, `$ref` 해석.
3. 계약 디렉터리는 특정 런타임에 종속되지 않으며 코드 생성물을 커밋하지 않는다.
4. 도메인 엔티티는 스펙 확정 전까지 만들지 않는다. 공통 봉투(오류/페이지/헬스)만 먼저 둔다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
| --- | --- |
| 선호 스택으로 앱부터 구현 | 스택/도메인 미확정 → 재작업 위험 |
| 문서만 작성하고 대기 | R-009("분석 후 멈추지 말 것") 위반 |
| 도메인 모델을 추정해 선설계 | 근거 없는 설계, 이후 폐기 가능성 |

## 결과

- 장점: 스택 결정과 무관하게 자산이 남는다. 계약이 항상 최신임이 보장된다.
- 비용: 계약과 구현의 이중 관리. Phase 4 에서 계약 테스트로 완화한다.
- 재검토 조건: 스펙 확정으로 도메인 스키마가 안정되면, 코드 생성 도입 여부를 재논의한다.
