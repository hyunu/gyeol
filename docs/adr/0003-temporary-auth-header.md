# ADR 0003 — 인증 부재 구간의 임시 사용자 식별

- 상태: 채택 (임시)
- 날짜: 2026-11-13
- 관련: D-01, `docs/10-domain-model.md` §11

## 맥락

인증 방식이 TBD(D-01)이지만 Recording/Conversation API 는 소유자 스코프가 필요하다.
인증을 먼저 만들면 범위가 커지고, 인증 없이 열면 다중 사용자 데이터가 섞인다.

## 결정

1. 모든 데이터 API 는 `X-User-Id` 헤더로 사용자를 식별한다.
2. 이 헤더는 **로컬 개발 환경에서만** 허용한다. `GYEOL_ENV` 가 `local` 이 아니면
   헤더가 있어도 `401 UNAUTHORIZED` 로 거부한다.
3. 헤더가 없거나 사용자가 없으면 `401`.
4. 코드에서 인증은 `AuthContext` 포트로 분리해, 실제 인증 도입 시 어댑터만 교체한다.

## 기각한 대안

| 대안 | 이유 |
| --- | --- |
| 인증을 먼저 구현 | D-01 미확정. 추측 구현은 재작업 |
| 쿼리 파라미터 `?userId=` | 로그·캐시에 남기 쉬움 |
| 헤더를 운영에서도 허용 | 누구나 타 사용자 데이터 접근 가능 (치명적) |

## 결과

- 로컬·테스트는 즉시 개발 가능.
- 운영 배포 시 `GYEOL_ENV=production` 만 설정하면 임시 경로가 **fail-closed** 로 막힌다.
- 실제 인증 도입 시 이 ADR 을 대체하는 ADR 을 작성한다.
