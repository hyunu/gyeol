# 작업 순서 (Work Order)

- 작성일: 2026-11-14
- 기준: `docs/01-requirements.md`, `docs/04-development-plan.md`, `docs/06-phase1-requirements.md`
- 목적: 남은 작업을 **의존성 순서**로 고정한다. 작업 ID 는 커밋 메시지에 남긴다(`feat(W-07): ...`).

## 1. 순서 원칙

1. **환경으로 검증 가능한 것 먼저** — DB·CI 처럼 지금 확인할 수 있는 것을 미루지 않는다.
2. **스키마를 굳히는 결정은 그 스키마를 쓰는 기능보다 먼저** — D-05(임베딩 차원), D-04(코덱).
3. **계약 → 구현 → 테스트 → 문서 갱신**을 한 커밋에서 처리한다(R-010).
4. **실물 의존 작업은 마지막 트랙** — `HW-PENDING` 해소 전에는 "완료"로 표기하지 않는다(R-011).
5. 문서와 코드의 상태가 다르면 **문서를 먼저 고친다**. 이후 판단의 기준을 신뢰할 수 있어야 한다.

## 2. 전체 의존 관계

```text
Track 0 (기준선 정합성)
   └─→ Track 1 (PostgreSQL 영속화) ─→ Track 3 (제품 기능) ─→ Track 5 (운영·릴리스)
                    │                        ↑
                    └─→ Track 2 (스키마 결정) ┘
Track 1 완료 후 Track 4 (하드웨어·iOS) 병렬 착수 가능
```
